소개

동국대학교 정보통신공학과에서 백엔드 개발을 공부하고 있습니다.

Spring Boot 기반 API 서버 개발부터 Docker, Kubernetes를 활용한 클라우드 인프라 구성까지, 코드가 작성되는 순간부터 운영 환경에서 동작하는 순간까지의 전반에 관심을 가지고 있습니다.

기술은 필요를 겪은 뒤에 넣는다는 원칙을 지킵니다. 콜드체인 관제 시스템에서는 5,000대 부하로 병목을 직접 확인한 뒤에야 Kafka와 TimescaleDB로 전환했고, 예측 모델도 "정확하다"고 주장하는 대신 통제된 벤치로 트레이드오프를 측정해 기본값을 정했습니다.

한 번 시작한 일은 어중간하게 끝내지 않고 더 나은 형태로 다듬어가는 태도를 중요하게 생각합니다.

coldchain — 콜드체인 IoT 관제·온도 이탈 예측 시스템

2026.07 · 개인 프로젝트 · 설계·개발 전담

임계값을 넘은 뒤 알리는 관제가 아니라, 넘기 전에 경고하는 시스템. 트래커의 온도·위치를 실시간 수집·이상탐지하고, 추세로부터 이탈 시각을 예측해 사전 경고한다. 예측이 무의미해지는 급변에는 예측을 즉시 무효화하고 확정 알림으로 전환하는 안전한 실패 설계.

  • 5,000 트래커·초당 1,000건 부하에서 병목을 실측한 뒤 Kafka·TimescaleDB 도입 — 대시보드 조회 p50 22.7초 → 412ms, 수집 p99 462ms → 90ms
  • 예측 모델 2종(선형회귀 / 뉴턴 냉각 물리 모델)을 같은 시드로 짝지어 벤치 — 오탐률 0.68 → 0.04, 우위가 아닌 트레이드오프로 규명해 기본값 선택
  • 화주(JWT)·수령기관(매직링크)·관리자(어드민 키) 역할별 인가 분리, 스코프 위반은 403이 아닌 404 존재 은닉으로 Testcontainers 통합 테스트에서 증명
