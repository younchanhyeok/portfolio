01소개

사용자의 업무 규칙을 시스템 동작으로 구현합니다. 모노플로우 인턴으로 GPU 실습 플랫폼 MonoLab을 개발하고 있습니다. 학생의 실습 시작부터 교사의 관리와 운영자의 사용량 확인까지 연결했습니다.

실습 화면이 열리는 것뿐 아니라 종료 이후도 확인했습니다. 실제 GPU에서 파일 보존과 동시 실습을 시험했고 자원 종료를 확인한 뒤 정산하도록 구성했습니다. 현재는 납품을 위한 개발·검증 단계이며 회사 망 서버 배포와 SSH 유지보수를 준비하고 있습니다.

CJ AI SW Wave에서는 콜드체인 개인 프로젝트의 처리 지연을 개선했습니다. 인턴 근무 중에는 안내 로봇을 행사장에서 운영하고 제품 오류를 재현해 보고했습니다. 구현 결과를 실제 사용 조건에서 확인하는 경험을 쌓고 있습니다.

실습 종료 버튼 너머, 정산까지

GPU 실습의 시작·종료·정산을 연결하고 실제 A100에서 검증했습니다. 학교·기관의 학생과 교사가 사용하도록 개발 중인 실습 플랫폼입니다. 역할별 권한과 실습 시간 관리부터 GPU 자원 회수까지 구현했습니다.

  • 사용 규칙 구현. 학생·교사·관리자의 접근 범위를 나눴습니다. 실습 전 선택 시간을 확보하고 실행 기록과 정산 기준을 함께 저장했습니다.
  • 종료와 정산 분리. Lab 접속 준비가 끝난 뒤 사용 시간을 계산합니다. 공급자의 GPU와 Notebook 종료를 확인한 뒤 정산을 확정하고 미사용 시간을 반환하도록 구성했습니다. 중복 정산도 방지했습니다.
  • 장애 대응. Hub와 별도로 동작하는 감시 프로세스로 GPU 회수를 처리했습니다. 사용 시간을 확정하기 어려운 장애 건은 운영자가 기록을 남겨 정산하도록 했습니다.
  • 실환경 검증. 실제 A100의 CUDA 연산과 두 학생의 별도 GPU 동시 실습을 확인했습니다. 파일 보존과 로그아웃을 시험했고 시간 만료·30분 미사용 종료·원장 분리도 확인했습니다.

다음 단계 시연 승인 후 회사 망 서버에 배포하고 직접 SSH로 유지보수할 예정입니다. GPU 실행 자원과 영구 저장소는 VESSL을 사용합니다. 현재 납품·운영 완료 단계는 아닙니다.

콜드체인 관제·온도 이탈 예측

22.7초의 기다림을 412ms로

가상 장비 5,000대 부하 시험에서 대시보드 조회 p50을 22.7초에서 412ms로 줄였습니다. 운송 중 온도·위치를 수집하고 온도 이탈 가능성을 알리는 개인 프로젝트입니다. 부하가 늘 때 쌓이는 처리 지연을 줄이는 작업을 진행했습니다.

대시보드 조회 p5022.7s→412ms
조회 타임아웃83%→0%
수집 요청 202 응답 p99462ms→90ms
  • 수집·저장 개선. Kafka와 TimescaleDB를 활용하고 장비별 메시지 키와 배치 저장을 적용했습니다. 중복되거나 늦게 도착한 데이터도 처리했습니다.
  • 작업 자원 분리. 수집과 예측의 실행 자원을 나누고 작업 큐 크기를 제한했습니다. 큐에서 거절된 작업을 계측하고 원본 저장과 후속 분석의 실패 처리를 분리했습니다.
  • 모델 선택. 두 예측 모델을 같은 조건에서 비교했습니다. 새 모델은 오탐이 줄었지만 놓침과 시각 오차가 늘어 기존 모델을 기본값으로 유지했습니다.

README에 기록한 로컬 시뮬레이터 결과입니다. 조건은 가상 장비 5,000대·초당 1,000건입니다. SSE 반영 지연은 개선 후에도 37.8초였으며 모든 후속 처리가 즉시 완료된 것은 아닙니다.

모노쥐 부스 안내 로봇

요청 성공에서 실제 목소리로

음성 서비스와 로봇 동작을 연결해 AI Festa 부스에서 운영했습니다. 방문객에게 먼저 인사하고 퀴즈와 대화로 제품을 소개하는 로봇입니다. 요청은 수락됐지만 소리가 나오지 않은 채 다음 단계로 넘어가는 문제를 수정했습니다.

  • 발화 기준 수정. 로봇 앱과 음성 API 사이의 WebSocket 규격을 변환하는 브리지를 구현했습니다. 실제 소리 출력 여부로 상태를 전환하고 발화가 없을 때 다시 시도하도록 했습니다.
  • 반복과 동작 조정. 방문객마다 퀴즈를 순환 배정했습니다. 음성 신호와 몸짓을 연결하고 얼굴 추적과 동작의 충돌을 조정했습니다.
  • 실행 환경 이전. 브리지를 로봇 내부의 systemd 서비스로 옮겼습니다. 재부팅·강제 종료 후 재연결을 시험하고 배포 확인과 롤백 절차를 정리했습니다.
  • 현장 운영. 10월 6~8일 행사장에서 운영했습니다. 인터넷 장애 이후 재연결을 확인했고 방문객에게 제품 기능과 이용 방법도 설명했습니다.

기반 SDK와 음성 모델을 활용했습니다. 현장에서 발생한 멈춤 사례의 원인은 확정하지 못했으며 이후 개선 과제로 남겼습니다.

Kubernetes 운영 분석 플랫폼

감시하는 시스템도 멈추지 않도록

운영 데이터 수집 장애를 수정하고 배포 자동화에 기여했습니다. 메트릭·로그·이벤트를 모아 AI 분석과 알림으로 연결하는 팀 프로젝트입니다. 저는 수집과 배포 영역을 맡았습니다.

  • 데이터 연결. Kubernetes API와 Prometheus·Loki에서 운영 데이터를 수집해 분석 모듈로 전달하는 백엔드 작업에 참여했습니다.
  • 수집 장애 수정. 스케줄러가 멈추는 문제에 대응해 Kubernetes 클라이언트를 수정했습니다. 실행 성능과 네임스페이스 범위 조회도 개선했습니다.
  • 배포 추적. 커밋 SHA를 이미지 태그로 사용하고 인프라 저장소의 이미지 버전을 자동 갱신하는 흐름에 기여했습니다. Redis 실행 권한과 노드 구성도 수정했습니다.

AI 분석 모델과 프런트엔드는 팀의 다른 담당 영역입니다. 개인 기여는 백엔드와 인프라 저장소의 커밋에서 확인할 수 있습니다.

  • 분석 흐름 구현. 기기·문자 정보를 저장하고 AI 분석을 요청했습니다. 반환된 점수를 위험 등급과 응답 형식으로 변환하고 오류 처리를 정리했습니다.
  • 호출 전 필터. 5자 미만이면서 숫자와 URL이 없는 문자는 AI 호출을 생략하고 안전으로 처리하는 조건을 추가했습니다.
  • 파트 간 연동. API 명세를 작성하고 앱 담당자와 연동했습니다. 팀 전체가 실제 데이터로 알림 수신부터 결과 표시까지 시험했으며 저는 최종 문서 초안도 맡았습니다.
