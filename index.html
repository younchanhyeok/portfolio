01소개

백엔드 개발을 바탕으로 AI 연동과 검증·운영까지 경험했습니다. Java·Spring Boot와 Python으로 API와 데이터 처리 기능을 개발하며 실제 사용 조건에서 동작을 확인해 왔습니다.

모노플로우 인턴으로 학교·기관용 GPU 실습 플랫폼 MonoLab을 개발했습니다. 계정과 GPU 환경 준비부터 실습 제어·시간 정산·비용 보고까지 연결했습니다. 실제 A100에서 주요 사용 흐름을 검증했으며 현재 시연과 배포를 준비하고 있습니다.

콜드체인에서는 부하 시험으로 조회 지연을 줄였고, 안내 로봇은 음성 AI를 연결해 AI Festa에서 운영했습니다. 제품 QA로 오류를 개선하고 현장에서 고객의 질문에 답하며 개발한 기능이 어떻게 쓰이는지도 살폈습니다.

MonoLab

실습을 여는 순간부터, 운영자가 확인할 비용까지

학교·기관의 GPU 실습 운영을 하나의 플랫폼으로 연결했습니다. 운영자는 계정과 GPU 환경을 준비하고 교사는 담당 수업을 관리합니다. 학생과 교사는 브라우저에서 실습하며 종료 후에도 파일을 이어서 사용할 수 있습니다. 사용 시간 정산과 내부 비용 보고까지 구현하고 실제 A100으로 검증했습니다.

  1. 01계정·자원 준비
  2. 02실습·작업 감시
  3. 03종료·시간 정산
  4. 04사용량·비용 보고
  • 실습 준비를 관리자 화면으로. 계정 발급부터 전용 GPU·영구 볼륨 생성, SSH 확인과 환경 설치, 시간 배정까지 연결했습니다. 기관·수업별 권한을 구분하고 교사의 개인 실습과 계정 복구도 지원합니다.
  • 실제로 쓴 시간만 차감. Lab 준비 완료부터 종료 요청까지 사용 시간을 계산합니다. GPU와 Notebook의 중지를 확인한 뒤 미사용 시간을 반환하며 중복 정산을 막았습니다. 준비와 종료 대기는 사용자 차감에서 제외합니다.
  • 작업은 보호하고 유휴 자원은 회수. 셀·터미널 작업을 감시해 출력 없는 연산은 유지하고 30분 미사용 시 종료합니다. Hub 중단 시에는 별도 감시 프로세스가 GPU를 회수하며 불명확한 사용량은 근거를 남겨 보정합니다.
  • 파일 정리부터 비용 확인까지. 저장공간 초과 시 실행을 제한하되 파일 저장·다운로드·삭제는 유지하는 정리 모드를 구현했습니다. 운영자는 기관·수업별 사용량과 준비·실습·종료 비용을 원본과 대조하고 CSV·XLSX로 확인할 수 있습니다.
  • 실제 GPU와 장애 상황 검증. A100의 CUDA 연산, 두 학생의 동시 실습과 원장 분리, 종료 후 파일 보존을 확인했습니다. 시간 만료·실제 30분 미사용 종료와 Hub 중단 복구를 시험했고 로컬 HTTPS 사용자 격리·DB 장애 복구도 검증했습니다.

진행 상태 기능 개발을 완료하고 시연·배포를 준비하고 있습니다. 시연 승인 후 회사 망의 Ubuntu 서버로 이전하고 직접 SSH로 유지보수할 예정입니다.

콜드체인 관제·온도 이탈 예측

22.7초의 기다림을 412ms로

가상 장비 5,000대 부하 시험에서 대시보드 조회 p50을 22.7초에서 412ms로 줄였습니다. CJ AI SW Wave에서 운송 중 온도·위치를 수집하고 온도 이탈 가능성을 알리는 서비스를 개발했습니다. 부하가 늘면서 조회 요청이 지연돼 수집·저장 구조와 작업 자원 배분을 개선했습니다.

대시보드 조회 p5022.7s→412ms
조회 타임아웃83%→0%
수집 요청 202 응답 p99462ms→90ms
  • 수집·저장 개선. Kafka와 TimescaleDB를 활용하고 장비별 메시지 키와 배치 저장을 적용했습니다. 중복되거나 늦게 도착한 데이터도 처리했습니다.
  • 작업 자원 분리. 수집과 예측의 실행 자원을 나누고 작업 큐 크기를 제한했습니다. 큐에서 거절된 작업을 계측하고 원본 저장과 후속 분석의 실패 처리를 분리했습니다.
  • 모델 선택. 두 예측 모델을 같은 조건에서 비교했습니다. 새 모델은 오탐이 줄었지만 놓침과 시각 오차가 늘어 기존 모델을 기본값으로 유지했습니다.

README에 기록한 로컬 시뮬레이터 결과입니다. 조건은 가상 장비 5,000대·초당 1,000건입니다. SSE 반영 지연은 개선 후에도 37.8초였으며 모든 후속 처리가 즉시 완료된 것은 아닙니다.

모노쥐 부스 안내 로봇

한 번의 인사가 대화로 이어질 때까지

대화가 이어지지 않던 로봇의 음성 처리 방식을 바꿔 AI Festa에서 운영했습니다. 처음 연결한 음성 인식·언어 모델·음성 합성 방식에서는 인사 한마디가 여러 요청으로 들어가고 응답도 늦었습니다. 방문객과 퀴즈를 주고받을 수 있도록 실시간 음성 API로 전환했습니다.

  • 음성 API 연동. MonoRouter에 실시간 모델 지원을 요청하고 연결 오류를 QA했습니다. 로봇 앱과 API의 메시지 규격을 변환하고 응답 시작·종료 신호를 생성하는 브리지를 직접 구현했습니다.
  • 같은 입력으로 비교. 녹음을 반복 입력하는 도구로 캐스케이드와 실시간 방식의 인식 결과·응답 시각·건수를 대조했습니다. 실시간 모델들도 직접 사용하며 대화와 발화 품질을 비교해 최종 모델을 선택했습니다.
  • 대화와 몸짓 연결. 실제 음성 출력에 맞춰 응대 단계를 진행하도록 수정했습니다. 퀴즈를 순환 배정하고 정답 반응에 몸짓을 연결했습니다.
  • 배포와 현장 운영. 브리지를 로봇 내부의 systemd 서비스로 옮기고 재부팅·강제 종료 후 재연결을 시험했습니다. 10월 6~8일 행사장에서 운영하며 인터넷 장애 이후 연결 복구를 확인했습니다.

기반 SDK와 음성 모델을 활용했습니다. 현장에서 발생한 멈춤 사례의 원인은 확정하지 못했으며 이후 개선 과제로 남겼습니다.

  • 데이터 연결. Kubernetes API와 Prometheus·Loki에서 운영 데이터를 수집해 분석 모듈로 전달하는 백엔드 작업에 참여했습니다.

  • 배포 추적. 커밋 SHA를 이미지 태그로 사용하고 인프라 저장소의 이미지 버전을 자동 갱신하는 흐름에 기여했습니다. Redis 실행 권한과 노드 구성도 수정했습니다.

개인 기여는 운영 데이터 수집과 배포 영역입니다. 백엔드·인프라 저장소의 커밋에서 구현과 수정 내용을 확인할 수 있습니다.

  • 분석 흐름 구현. 기기·문자 정보를 저장하고 AI 분석을 요청했습니다. 반환된 점수를 위험 등급과 응답 형식으로 변환하고 오류 처리를 정리했습니다.
